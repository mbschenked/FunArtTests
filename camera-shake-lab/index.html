Gotchas the source shows

Rotation is off by default

A new Wave Oscillator or Perlin pattern sets Rotation Amplitude Multiplier = 0. Pitch, Yaw and Roll do nothing until you raise it. The same goes for FOV Amplitude = 0.

Initial Offset Type defaults to Random

Each axis starts at a random spot on its wave, so two axes with the same Frequency still won't move together. Set them to Zero to get a straight diagonal or a known first direction.

Perlin Frequency is not Hz

Wave advances by Frequency × 2π per second, so Frequency 1 is one full swing. Perlin advances by Frequency lattice cells per second, so Frequency 1 is about one random bump. Perlin has no Initial Offset Type: it always starts at a random cell.

Blend In eats short shakes

Blend In Time defaults to 0.2 s and Blend Out Time to 0.2 s, both linear. On a 0.2 s kick that blend flattens the whole thing. Set Blend In Time to 0 for a punchy start.

Duration 0 means forever

Duration zero or less is infinite. The shake runs until you stop it. The lab shows the first 4 s.

Single Instance doesn't change the shape

It only decides what happens when the shake is played again while it's still running. True restarts the running one. False stacks a second copy.

How the engine computes it

Every frame, for each axis: offset += DeltaTime × Frequency × FrequencyMultiplier × 2π, then value = Amplitude × AmplitudeMultiplier × sin(offset) (WaveOscillatorCameraShakePattern.cpp:15–24). Perlin uses the same steps without the 2π and with PerlinNoise1D in place of sin (PerlinNoiseCameraShakePattern.cpp:7–16). Then everything, FOV included, is multiplied by the blend weight: time ÷ BlendInTime while blending in, times 1 − blendOutTime ÷ BlendOutTime while blending out (CameraShakeBase.cpp:173, 186). The lab runs those steps at 120 frames per second.

To aim a shake when you play it, use the Start Camera Shake node on the Player Camera Manager. Set Play Space to User Defined and pass a rotator in User Play Space Rot. Scale multiplies the whole shake.
